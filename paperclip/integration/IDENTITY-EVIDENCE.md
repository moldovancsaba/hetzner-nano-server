# Literal identity evidence export

The native exchange adapter prepares a separate copy of ClassScout public facts before creating an offer. It does not rewrite the factory's research facts or the application's records.

When a name is missing, the adapter may use a unique domain-matched page title that appears literally in the independently fetched text. When an address is missing, it may retain a unique literal street from that same page. A validated street-only claim can retain its contiguous comma-separated locality and state context when that complete address occurs uniquely on the page. Different streets and conflicting locality contexts remain distinct; ambiguity preserves the original evidence. Newlines are not joined, page text is not rewritten, and neither the searched market nor project label supplies a location.

The canonical public-claim contract still validates every exported value and quote. Sensitive or oversized evidence is refused by that contract. The original source digest, observation time and task reference remain unchanged. Existing source offers and request bytes are immutable; newly available literal claims produce a different evidence packet rather than modifying an acknowledged one. Existing capacity, retry and partial-discovery limits continue to apply.

OpenClaw independently refetches the page, validates the claims and ownership, checks youth suitability and asks the destination's location resolver to establish territory. A fuller exported address is evidence, not a qualification or permission to write.

The adapter adds no source fetch, search, model call, task or schedule. Release it through the exact-digest, idle-fenced module-only deployment helper. Its focused tests cover literal locality retention, invalid quote refusal, cross-street and ambiguous locality handling, immutable native facts and stable original-packet replay. Deployment evidence belongs in the generated release record and the OpenClaw implementation state.


## Per-project source policy

`source_exchange.project_policies` binds each native project to an exact scope and source-policy review_ref. New clients cannot reuse the original global NYC approval. The original single-project NYC configuration retains its existing policy_revision for compatibility; once the project roster expands, every project, including NYC, needs an explicit matching policy entry. Missing, mismatched or empty references hold the offer before its outbox reservation and emit the typed source-project-policy-required diagnostic. No source mapping or policy review is created by deploying this guard.
