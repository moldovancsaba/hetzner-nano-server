# JEV evidence probabilities

Publication and refresh call the scoped evidence probability service through `jev_workflow.py`. `/etc/jev-paperclip.json` owns off/shadow/assist and its threshold; only factory policy authorizes a write. Scoring is conditional SUPPORTED/UNKNOWN and experimental; it does not establish whole-page safety or contradiction. Existing deterministic checks, packet identity, daily reservations and exact readback remain binding.

The adapter binds one original source fact to its receipt and keeps a durable private outbox. On low support or an unchecked call, assist requests additional evidence. Source snapshots, actual outcomes and completed reviews have different contracts; a delivered outcome is not a training label. A contact-only refresh may use the provider name found literally on the fetched page as the evidence claim. No public source match is invented from generated packet content.

The private `/jev-review` broker uses the existing metered provider and shared budget to grade blind public evidence for the common JEV reviewed queue. It never receives student predictions or client outcomes. External credentials stay in the factory service; the broker and scoring tokens use systemd credentials.

Recovery: set the owned policy to shadow/off without deleting packets, outbox or native write receipts. An uncertain write must be reconciled before another effect. The owner-side JEV deployment helper uses an idle process fence, file checksum comparison and a restricted backup; it preserves independent native changes. Do not replace this worker with an older full checkout.

Deployment, tests, daily learning and current coverage are documented in the JEV repository's `docs/WORKFLOW_OPERATIONS.md` and generated delivery report. Source/version receipts are the measurement authority; this file states the operating contract.
